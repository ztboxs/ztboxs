## 把想法做成真正可用的产品

你好，我是 **ztboxs**。我是一名独立开发者，关注 **AI 应用、全栈产品和开发者工具**。

我喜欢从一个具体问题出发，串起产品设计、前后端开发与部署迭代。比起堆叠技术名词，我更在意：东西是否好用、系统是否清晰、需求是否真的被解决。

**目前关注的方向**

- **AI 与实际工作流**：让模型与工具协作，而不只是增加一个聊天框。
- **从想法到产品**：用小规模原型验证需求，再根据反馈继续打磨。
- **开发者体验**：减少重复操作，让开发、测试和交付更顺畅。

<a id="projects"></a>
## 公开项目

下面是可以直接查看的代码与实验。具体功能和使用方式以各仓库文档为准。

### [mcp-demo](https://github.com/ztboxs/mcp-demo)
**让图片压缩成为 AI 可以调用的工具。**

基于 MCP 的图片压缩服务，提供单张和批量压缩，并提供可选的 HTTP 接口。探索把一个明确的小任务接入 AI 工作流。

`Python` `MCP` `FastAPI` · [查看代码 →](https://github.com/ztboxs/mcp-demo)

### [Sips-Sober](https://github.com/ztboxs/Sips-Sober)
**围绕调酒场景展开的全栈应用探索。**

采用 React 与 Spring Boot，围绕酒柜管理、配方发现和调酒指导组织产品体验，把具体场景与前后端工程连接起来。

`React` `TypeScript` `Spring Boot` · [查看代码 →](https://github.com/ztboxs/Sips-Sober)

### [SaaSTemplate](https://github.com/ztboxs/SaaSTemplate)
**给下一次 Web 产品实验一个更清晰的起点。**

基于 React、TypeScript 与 Vite 的前端模板，组织了主题切换、国际化、路由和通用组件，减少从零搭建界面的重复工作。

`React` `TypeScript` `Vite` `Tailwind CSS` · [查看代码 →](https://github.com/ztboxs/SaaSTemplate)

## 我的构建习惯

**先理解问题，再缩小范围，尽早做出可运行的版本。**

用反馈决定下一步，用清晰的边界控制复杂度。让代码、文档与实际行为尽量保持一致，也给后续维护留出空间。
